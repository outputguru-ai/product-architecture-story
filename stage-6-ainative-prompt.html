大模型启蒙时代

2022 – 2023 · 当大模型 API 成为新的基础设施——但产品架构仍是传统的，AI 只是"功能插件"

产品架构演进之旅 · 面向 AI 产品经理的叙事课件

单体 → 分层 → SOA → 微服务 → 云原生 → Prompt → RAG+Agent → Multi-Agent
01 / 起源

为什么突然所有人都在写 prompt？

2022 年 11 月，ChatGPT 发布。两个月内获得 1 亿用户——成为历史上增长最快的消费级产品。那一刻，软件世界的规则被改写了：以前需要写代码才能做的事，现在用自然语言就能做。

⚠ 重要说明：这不是 AI Native 架构
严格来说，Prompt 时代属于 "AI-Enhanced（AI 增强）"，而非 "AI-Native（AI 原生）"。它的架构本质上仍是传统 Web/App 架构 + 一个 OpenAI API 调用。AI 在这里是"功能插件"，不是"架构假设"。真正的 AI Native 思考要等到 RAG + Agent 时代才开始。本阶段的价值在于：它证明了"自然语言可以成为通用接口"——这是 AI Native 的思想前夜。

要理解 Prompt 时代为什么爆发，我们必须回到一个根本性的认知转变：从"代码是接口"到"语言是接口"。在 ChatGPT 之前，人与软件的交互必须通过图形界面（GUI）或编程语言（API）。但大语言模型证明了一件事：自然语言本身就可以是接口——你说"帮我写一封辞职信"，AI 就写；你说"用 Python 算一下斐波那契数列"，AI 就写代码。

"我们用了六十年教计算机按规则思考。现在我们终于教会了它们按经验思考。" —— 一位 AI 研究员对 Transformer 时代的评述

五股推动力：

五股推动力

① Transformer 架构的突破（2017）：Google 论文《Attention Is All You Need》提出了"注意力机制"，让模型能同时看到整段文本的上下文。这个架构的扩展性惊人——参数越大，能力越强。这是大语言模型的技术根基。

② GPT-3 与"涌现能力"（2020）：OpenAI 发布的 GPT-3 有 1750 亿参数。它第一次让人们意识到：当模型足够大时，它会"突然学会"从未专门教过的事情——从几个例子中学新语言、零样本完成新任务。AI 从"窄领域专家"变成了"通才"。

③ ChatGPT 的产品破圈（2022）：ChatGPT 不是技术突破，而是产品突破——它用"对话界面"让普通人第一次直接感受到 AI 的力量。两个月 1 亿用户证明了：对话是最自然的交互方式。

④ API 经济成熟（2020–2022）：OpenAI API 让开发者像调用数据库一样调用大模型。Hugging Face 让模型发布像发布 npm 包一样简单。AI 能力民主化开始了。

⑤ 提示工程成为学科（2023）：人们发现，写提示词不是"随便问问"，而是一门需要技巧的艺术。角色设定、示例引导、思维链……好的提示词能让输出质量提升 10 倍。"Prompt Engineer"成为 2023 年最热门的新职位。

核心认知转变：从"规则驱动"到"数据驱动"。传统软件是人类把知识编码成规则；Prompt 时代的软件是机器从数据中学习知识。软件的"智能上限"不再取决于程序员的想象力，而取决于数据和提示词的设计。

02 / 人物

那个时代的人，在干什么

2022–2023 年，科技公司的办公室里出现了一个全新角色：Prompt Engineer。他们不写代码，但每天和提示词打交道；他们不设计数据库，但设计"AI 如何理解用户"。

小张 · Prompt Engineer

2023 年 / AI 创业公司
小张的工位上只有一台笔记本，屏幕上是 ChatGPT 的界面。他的工作是写提示词——不是随便写，而是经过几十次 A/B 测试找到"最优提示模板"。他会用"角色设定"（"你是一位资深产品经理"）来提升输出质量；用"思维链"（"请一步一步思考"）来改善推理能力。他最骄傲的时刻是：用一个精心设计的提示词，让 AI 生成了一份被老板认可的竞品分析报告。他最头痛的是：AI 偶尔会"一本正经地胡说八道"——他必须把"事实核查"写入提示词中。

小李 · 传统产品经理

2023 年 / 互联网公司
小李最初对 ChatGPT 持怀疑态度："这不就是个高级搜索引擎吗？"但用了两周后，她的工作流被彻底改变了。她用 ChatGPT 写 PRD 初稿、生成用户故事、整理会议纪要。以前需要半天的文案工作，现在 10 分钟搞定。但她也在焦虑："如果 AI 能写 PRD，那我还有什么价值？" 她的答案是：从"写文档的人"转型为"定义问题的人"——AI 擅长回答"怎么做"，但她需要确保问的是"做对了什么"。

小王 · 普通用户 / ChatGPT 早期采用者

2023 年 / 各行各业
小王是一名市场专员，第一次用 ChatGPT 时感觉"像在和一位超级聪明的朋友聊天"。他用它写英文邮件、总结长文章、帮朋友写情书。但他也踩过坑：有一次让 ChatGPT 查一个法律条文，AI 给出的条文编号是编造的——这让他意识到：AI 不是百科全书，它是一个"很会说话但可能犯错"的对话伙伴。从那以后，他把 AI 当作"草稿生成器"，而不是"事实查询器"。
"2023 年最颠覆我认知的瞬间，是看到一位 60 岁的会计阿姨用 ChatGPT 写了一封完美的英文商务邮件——她从未学过编程，但她现在能'编程'了。" —— 一位科技观察者的记录
03 / 产品

那个时代诞生了什么

Prompt 时代的产品分为两类：直接面向用户的"AI 对话产品"，和面向开发者的"AI API 与工具"。

ChatGPT

2022 · 大语言模型对话产品

AI 时代的"浏览器"——最普适的 AI 交互界面。用户用自然语言与模型对话，获取信息、生成内容、辅助思考。两个月内 1 亿用户，证明了对话即界面的产品范式。

OpenAI API / GPT-3 API

2020 · AI 基础设施服务

让 AI 能力"像水电一样"可被调用。开发者不需要自己训练模型，只需发送一段文字，就能获得模型的回复。开创了"模型即服务"（MaaS）的商业模式。

GitHub Copilot

2021 · AI 编程助手

在 IDE 中实时预测下一行代码。标志着 AI 从"独立应用"走向"嵌入工具"——它不在另一个窗口里，而就在你写代码的地方。

Jasper / Copy.ai

2021 / 2020 · AI 文案写作

面向营销人员的 AI 写作工具。输入"为一款新的咖啡机写社交媒体文案"，AI 生成 10 个版本供选择。它们证明了 AI 在结构化创意工作中的商业价值。

Notion AI

2023 · AI 生产力工具

把 AI 能力嵌入到日常办公场景中。在 Notion 文档里按空格键，AI 就能帮你续写、总结、翻译。代表了"AI 无处不在"的产品趋势。

Midjourney / DALL-E / Stable Diffusion

2022 · AI 图像生成

让文字描述直接变成图像。Midjourney 以艺术品质感著称；Stable Diffusion 开源，让任何人都能在本地运行。它们颠覆了图像创作——从"用手画"变成"用嘴说"。

04 / 认知

那个时代的人，心里在想什么

Prompt 时代不仅带来了新产品，更带来了对"软件""智能""人机交互"的全新认知。

认知一：提示 = 编程

人们开始相信，写提示词是一种新的编程方式——不是用 Python 或 Java，而是用自然语言"指挥"AI。一个精心设计的提示词可以让模型从"胡说八道"变成"专业顾问"。这引发了争论：提示工程是"真正的技能"还是"临时的工作"？目前的主流观点是：它既是当下的核心能力，也是未来会被抽象掉的中间层——就像早期的网页开发需要手写 HTML，现在的设计师用 Figma 拖拽就能生成代码。

认知二：自然语言 = 新接口

在 Prompt 时代之前，软件的接口是按钮、表单、命令行。但现在，自然语言本身成为了最自然的接口。用户不需要学习软件的术语，只需要用日常语言描述需求。这对产品设计的影响是深远的：未来的产品可能不再需要复杂的导航菜单，而是一个对话框。

认知三：涌现 = 魔法

GPT-3 让人们第一次亲眼见证了"涌现"（Emergence）——当模型规模达到某个临界点时，它会突然展现出训练时并未明确设计的能力。这种"量变引起质变"的现象让人们对 AI 的潜力充满了想象，也让一些人感到不安：如果 AI 的能力是我们无法预测的，那我们如何确保它的安全？

认知四：不确定性 = 需要学习管理

AI 的"幻觉"（一本正经地胡说八道）让人们意识到：AI 的输出不是事实，而是概率。 这迫使用户改变使用方式：把 AI 当作"草稿生成器"而非"权威来源"；对关键信息进行人工核实；学会判断什么任务适合交给 AI、什么不适合。这种"与不确定性共处"的心态，是 Prompt 时代用户最核心的认知转变。

05 / 关键词

关键词词典

Prompt 时代创造了一套全新的概念体系。这些词是理解这个时代思维方式的关键。

KEYWORD 01

大语言模型
LLM (Large Language Model)

基于 Transformer 架构、在海量文本上训练出来的巨型神经网络。核心能力：理解自然语言、生成连贯文本、推理、翻译。通俗理解：一个读过互联网上所有文字的"超级读者"，你问它任何问题，它都能基于"读过的书"给出合理回答。代表：GPT-4、Claude、LLaMA。

KEYWORD 02

提示工程
Prompt Engineering

设计和优化与 LLM 交互的"指令"的艺术。核心技巧：角色设定（"你是一位资深产品经理"）、示例引导（Few-shot）、思维链（Chain-of-Thought）。通俗理解：不是"问 AI 问题"，而是"教 AI 如何回答"。

KEYWORD 03

零样本 / 少样本
Zero-shot / Few-shot

Zero-shot：不给任何示例，直接让 AI 完成任务。Few-shot：给 2–5 个示例，让 AI 模仿示例的风格或格式完成任务。通俗理解：零样本 = "直接考"，少样本 = "给几道例题再考"。

KEYWORD 04

温度
Temperature

控制 AI 输出随机性的参数。Temperature = 0 时，AI 总是选择"最可能"的下一个词，输出更确定、更保守；Temperature = 1 时，AI 更愿意选择"不太可能但有趣"的词，输出更有创意但更不可控。通俗理解：Temperature 低 = 严谨的会计师，Temperature 高 = 浪漫的诗人。

KEYWORD 05

令牌
Token

LLM 处理文本的最小单位。一个英文单词 ≈ 1.3 个 token，一个中文字 ≈ 1.5–2 个 token。GPT-4 按 token 计费，输入和输出分别计价。通俗理解：token 是 AI 的"字数"，但和人类的字数不完全一样。

KEYWORD 06

上下文窗口
Context Window

模型能"记住"的文本长度。GPT-4 早期是 8K tokens（约 6000 字），Claude 3 支持 200K tokens（约 15 万字）。窗口越大，AI 能"读"的材料越多。 如果材料太长装不进窗口，就需要 RAG（检索增强）技术。

KEYWORD 07

幻觉
Hallucination

AI 生成看似合理但实际错误的信息。比如编造不存在的法律条文、虚构人物的生平、给出错误的数学答案。通俗理解：AI "吹牛"了。 这是大语言模型最大的可靠性问题，也是 RAG 技术诞生的直接原因。

KEYWORD 08

涌现能力
Emergent Abilities

当模型规模达到某个临界点时，突然展现出训练时并未明确设计的能力。比如 GPT-3 在没有专门训练的情况下就能进行算术推理、代码生成。通俗理解：就像水加热到 100°C 突然沸腾——量变引起质变。

关键词之间的联系

  • Transformer 架构→ 支撑 →LLM 训练→ 规模扩大 →涌现能力→ 产生 →Few-shot 学习能力
  • 提示工程→ 利用 →Few-shot / Zero-shot→ 激发 →LLM 潜在能力
  • Temperature→ 控制 →输出随机性→ 影响 →创意 vs 准确性权衡
  • Context Window→ 限制 →单次输入长度→ 催生 →RAG 技术（下一阶段）

易混淆概念辨析

Zero-shot vs Few-shot vs Fine-tuning
Zero-shot（零样本）

不给任何示例，直接提问。适合通用任务。成本低，但效果可能不稳定。

vs
Few-shot（少样本）

给 2–5 个示例，让 AI 模仿。无需训练，效果通常比 Zero-shot 好。

Fine-tuning（微调）

用大量领域数据继续训练模型。成本高，但效果最精准。需要 ML 专业知识。

vs
总结

Zero-shot/Few-shot 是"使用技巧"，Fine-tuning 是"模型改造"。产品经理通常从 Few-shot 开始。

High Temperature vs Low Temperature
Low Temperature（0–0.3）

输出更确定、更保守、更"正确"。适合：事实问答、代码生成、数据分析。

vs
High Temperature（0.7–1.0）

输出更有创意、更多样、更"有趣"。适合：头脑风暴、营销文案、故事创作。

《ChatGPT Prompt Engineering for Developers》

吴恩达 / OpenAI · 在线课程 · 免费

Prompt Engineering 的权威入门课。吴恩达用通俗的语言讲解：如何写有效的提示词、如何使用 Few-shot 示例、如何让 AI 输出结构化数据（JSON）。课程假设你不懂深度学习，只要求你会用 ChatGPT。产品经理学完就能立刻在工作中应用。

免费 即学即用

《Generative AI for Everyone》

吴恩达 · DeepLearning.AI · 在线课程 · 免费

专为非技术人员设计的生成式 AI 入门课。不讲算法，只讲应用：生成式 AI 是什么？它能做什么？不能做什么？如何在企业中应用？课程包含大量实际案例，是产品经理理解 AI 能力的最佳起点。

零基础 商业视角

OpenAI Cookbook

OpenAI · 开源文档 · 免费

官方推出的实战代码示例集，涵盖：文本分类、情感分析、问答系统、代码解释等常见场景。虽然是代码示例，但每篇都有详细的"业务场景说明"——产品经理可以跳过代码，只读场景分析和最佳实践。

实战案例 场景驱动

大模型启蒙时代的启示

本阶段的核心突破是：自然语言成为了人与软件之间的通用接口。 写提示词的能力——如何清晰地表达需求、如何结构化地引导 AI——将成为未来产品经理的核心技能之一。

但更重要的是一个认知区分："把 AI 塞进去" ≠ "为 AI 重新设计"。Prompt 时代的 AI 是功能插件——就像汽车上加装 GPS。而 AI Native 时代的 AI 是发动机——没有它，产品根本不存在。这个区别，将在阶段七和阶段八中变得清晰。

Prompt 时代也暴露了 LLM 的根本局限：幻觉、知识截止、无法访问私有数据。 这些问题催生了真正的 AI Native 演进——RAG 和 Agent。

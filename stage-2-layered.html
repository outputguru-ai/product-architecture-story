分层架构时代

产品架构演进之旅 · 面向 AI 产品经理的叙事课件

01 / 起源

从"一坨代码"到"三层楼房"

单体架构运行了二十多年，企业越来越发现一个问题：代码像一团越缠越紧的毛线，动一根线，整团都在抖。而与此同时，一场更大的风暴正在酝酿——互联网来了。

要理解分层架构为什么诞生，我们必须先回到单体架构晚期的痛苦。到了 1980 年代末，大型企业的软件系统已经积累了数十万甚至上百万行代码。所有的界面逻辑、业务规则、数据操作都混在一起。一个新来的程序员想修改一个报表功能，结果不小心把订单模块搞坏了——因为它们是同一堆代码。

" spaghetti code（意大利面条式代码）——你想找一根面条，结果发现所有面条都缠在一起。" —— 1990 年代软件工程界的流行比喻

关键转折点不是某一个单一事件，而是四股力量的汇聚：

四股推动力

① 互联网诞生（1991-1995）：Tim Berners-Lee 在 1991 年发布了第一个网页浏览器，1993 年 Mosaic 让普通人也能上网，1995 年 Netscape 上市引发了互联网热潮。企业突然意识到：我的系统不能只给内部员工用了，它要面对全世界的用户。这意味着系统必须能同时服务成千上万的人，而且界面必须是图形化的网页，而不是绿色的命令行终端。

② Java 语言革命（1995）：Sun 公司发布了 Java，喊出"Write Once, Run Anywhere"。这对企业来说意味着什么？以前写的大型机程序只能在 IBM 机器上跑，现在同一套代码可以在 Windows、Mac、Unix 上跑。企业第一次有了跨平台的选项，不再被单一硬件厂商绑架。

③ 面向对象编程成熟（1980s-1990s）：C++（1985）和 Java（1995）把"对象"的概念带入了主流。工程师们开始思考：如果把代码组织成一个个独立的"对象"，每个对象只负责一件事，是不是更好维护？这种思维方式直接催生了"分层"——既然对象可以独立，那不同职责的代码为什么不能分开？

④ 企业竞争加速（1990s）：全球化竞争加剧，企业需要更快地响应市场。但单体架构的修改周期以月计算。业务部门说"我们下周要做促销活动"，IT 部门说"排期在三个月后"。这种速度上的错配让企业开始质疑：是不是我们的软件本身出了问题？

那么，科学认知发生了怎样的变化？在早期，人们认为"程序 = 一段连续的指令序列"——从上到下依次执行。但到了 1990 年代，软件工程的学术界开始流行一个新概念：关注点分离（Separation of Concerns）。核心思想是：人类大脑处理复杂事物的最佳方式是分而治之。不要试图同时考虑所有事情，而是把问题拆成几个层次，每一层只关心自己的问题。

为什么是分层而不是别的方向？这个问题其实很有趣。人类天生喜欢分层——公司里有管理层、执行层、操作层；社会里有上层、中层、下层；甚至我们的大脑皮层也是分层的。分层架构不是某个天才的灵光一闪，而是人类认知模式在软件中的投射。"把显示的事情交给一层，把业务规则交给一层，把数据存取交给一层"——这个想法如此自然，以至于当它被提出来后，几乎所有人都觉得"对啊，本来就该这样"。

但请注意：分层架构并没有打破单体。代码逻辑上分成了三层，但物理上仍然部署在同一个服务器上。这就像一栋三层楼房——虽然每层功能不同，但它们仍然在同一栋建筑里。真正把建筑拆开的，还要再等十年。

关键事件时间线

  • 1991 Tim Berners-Lee 发布第一个网页浏览器和 HTTP 协议，World Wide Web 诞生。
  • 1993 Mosaic 浏览器发布，图形化网页进入大众视野。普通人第一次能在网页上看到图片。
  • 1994 Amazon 成立，Yahoo 成立。电子商务时代萌芽。"在网上卖东西"从幻想变成现实。
  • 1995 Java 发布、JavaScript 诞生、Windows 95 发布、Netscape 上市。这是互联网革命的元年。
  • 1996 J2EE 规范开始制定（当时叫 J2SE + Servlet），企业级 Java 应用服务器概念诞生。
  • 1998 Google 成立。"搜索"成为互联网的入口。同年，Sun 发布 J2EE 1.0，分层企业应用有了标准。
  • 2001 互联网泡沫破裂，但留下的基础设施（浏览器、Java、Web 服务器）成为下一代应用的基石。
02 / 人物

那个时代的人，在干什么

1990 年代到 2000 年代初，办公室里的风景已经大不一样。穿孔卡片消失了，取而代之的是 CRT 显示器和鼠标。而最关键的是——互联网让"产品经理"这个角色开始萌芽。

小陈 · Java 程序员

1998 – 2005 / 互联网泡沫前后
小陈的工位上放着一台CRT 显示器（又大又沉，辐射能把脸烤热），屏幕上是深蓝色的 IDE 界面。他正在写一个 Servlet——这是 Java 处理 Web 请求的基础组件。他每天都要纠结一个问题："这段代码该放在 Controller 层还是 Service 层？" 他的团队刚转型用了Struts 框架，每个人都在学习 MVC 怎么写。小陈最骄傲的事情是：他写了一个 JavaBean，被三个不同模块复用了——这在单体时代是不可想象的。但他最痛苦的事情是：每次改完代码要重启整个 Tomcat 服务器，等 2 分钟才能看到效果。"要是能把界面和逻辑分开部署就好了"——他常常这样想，但不知道十年后这真的会实现。

小美 · 需求分析师 / UML 画图师

1995 – 2005 / 最接近"产品经理"前身
小美的桌上堆满了Rational Rose 打印出来的 UML 图——用例图、类图、时序图、状态图……她用这些图和开发团队"对话"。在还没有"产品经理"这个词的年代，她就是业务和技术之间的翻译官。业务部门说"客户下单后应该收到确认邮件"，小美要把这句话翻译成：一个用例（Use Case），触发一个时序图中的消息流，最终映射到数据库表的一个字段变更。她最大的武器不是代码能力，而是画图能力。她常常加班到深夜，因为明天要给客户演示系统原型——而"原型"是一堆静态 HTML 页面，点一下链接跳到下一张静态页面。但客户看了之后惊呼："这和真的一样！"

阿强 · 网吧里的普通网民

1998 – 2005 / 第一代互联网用户
阿强每周去两次网吧，一小时 3 块钱。他打开 Netscape 或 IE 浏览器，在地址栏输入 www.yahoo.com，看到一个密密麻麻的分类目录——就像一本黄页。他点击"体育"，找到"足球"，再找到"意甲"，终于看到新闻。他也用 Hotmail 收发邮件，用 ICQ 和网友聊天（那个"哦哦"的敲门声是时代的标志）。他不知道什么是 MVC，什么是三层架构，但他隐隐约约感觉到：网页上的东西越来越丰富了——以前只能看文字，现在能看图片、能填表单、甚至能在 eBay 上买东西。他点击"购买"按钮时，根本不知道背后有一个 Java Servlet 正在处理他的请求，一个 Oracle 数据库正在扣减库存，一个邮件服务器正在给他发确认信。但这正是分层架构的意义：用户不需要知道底层，每一层都默默做好自己的事。
"1998 年，我第一次在浏览器里填了一个表单，点提交，第二天收到了 UPS 送来的包裹。那一刻我知道，世界变了。" —— 一位早期 Amazon 用户的回忆
03 / 产品

那个时代诞生了什么

分层架构时代是现代互联网产品的摇篮。我们今天使用的几乎所有互联网服务，都可以在这个时代找到雏形。

Java / J2EE 平台

1995 · 编程语言 & 企业平台

Sun 公司推出的跨平台编程语言及企业级开发规范。J2EE 定义了 Servlet（处理请求）、JSP（生成页面）、EJB（业务逻辑）、JDBC（数据库访问）等分层标准。它让"分层"从个人习惯变成了行业标准。

Apache HTTP Server

1995 · Web 服务器

世界上使用最广泛的 Web 服务器软件。它就像一个"前台接待员"——所有用户请求先到它这里，它再把请求转给后面的应用服务器处理。这是分层架构中"表示层"的基础设施。

Amazon.com

1994 · 电子商务

从在线书店起步， Jeff Bezos 选择了图书作为切入点因为"图书品类最多、标准化程度最高"。Amazon 是最早将分层架构用于大规模电商的企业之一——前端网页、订单处理、库存管理、支付网关，各司其职。

Google 搜索引擎

1998 · 搜索 & 信息检索

PageRank 算法让搜索结果质量远超 Yahoo 的人工目录。Google 的技术架构从一开始就采用了分层设计——爬虫层、索引层、查询层、展示层——虽然当时还是单体部署，但逻辑上已经高度分层。

SAP R/3

1992 · 企业资源计划

SAP 从大型机时代的 R/2 迁移到 C/S 架构的 R/3，支持 Windows 和 Unix 客户端。它将财务、人力资源、生产、销售模块分层设计，虽然仍在同一个代码库中，但已经能按模块独立升级。

eBay 在线拍卖

1995 · C2C 电商

Pierre Omidyar 在 Labour Day 周末搭起了 eBay 的第一个版本。它证明了陌生人之间可以在互联网上完成交易。eBay 的早期架构是典型的三层：ASP 页面（表示层）+ COM 组件（业务层）+ SQL Server（数据层）。

04 / 认知

那个时代的人，心里在想什么

分层架构不仅改变了代码的组织方式，更深刻地改变了人们对软件的认知。这四个心理转变，奠定了现代软件工程的基础。

认知一：分层 = 秩序 = 可控

人们开始相信，把复杂系统拆成清晰的层次，就像把杂乱的衣柜按季节分类——找东西更快，整理更容易。"表示层只管显示，业务层只管规则，数据层只管存取"——这种清晰的边界感给了工程师巨大的心理安全感。不管系统多复杂，只要层次清晰，就觉得"尽在掌握"。

认知二：对象 = 复用 = 省钱

面向对象编程带来的最大心理冲击是："原来我可以写一段代码，然后在很多地方重复使用！" 这在商业上极具诱惑力——"写一次，到处用"意味着开发成本大幅下降。企业开始相信，投资好的软件设计（分层 + 对象）能在长期节省更多的钱。

认知三：Web = 新世界的大门

对非技术人员来说，浏览器是一扇通往未知世界的窗。"原来我不需要装任何软件，只要在浏览器里输入地址就能用"——这种认知彻底改变了软件的交付方式。对企业来说，这意味着客户可以在世界任何地方访问系统。分层架构让这种全球可访问性成为可能。

认知四：软件 > 硬件（价值认知翻转）

1990 年代发生了惊人的认知逆转：软件开始比硬件更值钱。Microsoft 的市值超过 IBM，Oracle 的数据库比服务器更贵。人们意识到：硬件会贬值，但好的软件设计可以持续创造价值。这种认知推动了企业对软件架构的投资——愿意花更多钱请架构师做好分层设计。

"1995 年之前，IT 部门是'成本中心'；1995 年之后，越来越多的公司开始把 IT 看作'竞争力来源'。" ——《The World is Flat》作者 Thomas Friedman
05 / 关键词

关键词词典

分层架构时代诞生了一套全新的词汇。这些词今天仍在广泛使用——理解它们，你就理解了现代软件工程的底层逻辑。

KEYWORD 01

MVC
Model-View-Controller

一种软件设计模式，把应用分成三部分：Model（数据）负责存取数据，View（视图）负责显示界面，Controller（控制器）负责接收用户输入并协调 Model 和 View。就像一家餐厅：Model 是后厨（准备食材），View 是摆盘（端上桌的样子），Controller 是服务员（把客人的需求传达给后厨，再把菜端上来）。

KEYWORD 02

三层架构
Three-Tier Architecture

把系统分为表示层（Presentation）、业务逻辑层（Business Logic）、数据访问层（Data Access）。注意：三层架构和 MVC 有重叠，但不完全相同。三层更强调物理部署的分层（可以分开部署在不同服务器上），而 MVC 更强调代码内部的职责分离。很多系统同时采用两者。

KEYWORD 03

面向对象
Object-Oriented Programming, OOP

把代码组织成"对象"，每个对象封装了数据（属性）和行为（方法）。就像现实世界的物体——一辆"汽车"对象有颜色、品牌（属性），也能启动、刹车（方法）。面向对象的核心思想是封装、继承、多态，它让代码更容易复用和维护。

KEYWORD 04

J2EE / .NET
Java 2 Platform Enterprise Edition / .NET Framework

两个竞争的企业级开发平台。J2EE（Sun，后改名 Java EE）是 Java 阵营的标准，.NET（Microsoft，2002 年发布）是微软的回应。它们都提供了分层开发所需的基础设施：Web 容器、事务管理、数据库连接池、安全框架等。选择 J2EE 还是 .NET，曾是企业 IT 部门最纠结的战略决策之一。

KEYWORD 05

Servlet / JSP / ASP / PHP
Server-side Web Technologies

这些是 1990 年代生成动态网页的技术。Servlet（Java）和 JSP（JavaServer Pages）是 J2EE 的表示层技术；ASP（Active Server Pages，微软）用 VBScript 生成页面；PHP 是开源的轻量级选择。它们共同的使命是：当用户在浏览器里请求一个页面时，服务器端动态生成 HTML 返回给浏览器。

KEYWORD 06

UML
Unified Modeling Language

统一建模语言，一套图形化的软件设计符号系统。用例图（描述用户需求）、类图（描述代码结构）、时序图（描述交互流程）……UML 让非程序员也能"看懂"软件设计。虽然后来被敏捷开发运动部分否定，但它代表了那个时代对"软件工程可视化"的追求。

KEYWORD 07

B/S 架构
Browser-Server Architecture

浏览器-服务器架构。与早期的 C/S（Client-Server，需要安装专用客户端软件）不同，B/S 只需要一个浏览器就能使用系统。对企业来说，这意味着零部署成本——用户不需要安装任何软件，打开浏览器就能用。这是互联网普及的关键技术前提。

KEYWORD 08

应用服务器
Application Server

专门运行业务逻辑的服务器软件。Web 服务器（如 Apache）只负责接收 HTTP 请求和返回静态文件，应用服务器（如 Tomcat、WebLogic、WebSphere）负责运行动态的业务代码。在三层架构中，应用服务器就是"业务逻辑层"的物理载体。

关键词之间的联系

  • 互联网 → 催生 → 浏览器 → 需要 → B/S 架构 → 推动 → Web 技术（Servlet/JSP/ASP/PHP）
  • 面向对象 → 催生 → MVC 模式 → 推广到 → 三层架构 → 需要 → 应用服务器
  • 分层架构 → 需要被 → 可视化表达 → 催生 → UML → 被 → 需求分析师 / 早期产品经理 → 使用
  • Java → 演化出 → J2EE → 与 → .NET → 竞争 → 企业级开发平台市场

易混淆概念辨析

概念对比
MVC

一种设计模式，关注代码内部的职责分离。Model、View、Controller 是逻辑上的划分，不一定对应物理部署。

三层架构

一种部署架构，关注系统的物理分层。表示层、业务层、数据层可以部署在不同的机器上。

C/S 架构

客户端-服务器。需要安装专用客户端软件，功能强大但部署麻烦。适用于企业内部系统。

B/S 架构

浏览器-服务器。只需浏览器即可访问，部署简单但功能受限（早期）。适用于互联网应用。

J2EE

Java 的企业级规范，跨平台，开源生态丰富。运行在 Tomcat、WebLogic 等容器中。

.NET

微软的企业级框架，与 Windows 深度集成，开发工具（Visual Studio）强大。早期不跨平台。

面向过程

按步骤依次执行（第一步做什么，第二步做什么）。代码像一份说明书。

面向对象

把代码组织成互相协作的"对象"。代码像一群互相发送消息的小机器人。

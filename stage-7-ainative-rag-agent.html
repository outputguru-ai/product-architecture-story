AI Native RAG + Agent 时代

2023 – 2024 · 给 AI 装上记忆和手脚——检索增强生成、工具调用、自主决策

产品架构演进之旅 · 面向 AI 产品经理的叙事课件

单体 → 分层 → SOA → 微服务 → 云原生 → Prompt → RAG+Agent → Multi-Agent
01 / 起源

为什么 Prompt 不够了？

ChatGPT 的横空出世让所有人看到了 AI 的潜力。但很快，一个残酷的现实浮出水面：大语言模型会"一本正经地胡说八道"——它 hallucinate（幻觉），它没有访问企业私有数据的权限，它对 2022 年之后发生的事情一无所知。 2023–2024 年，整个行业意识到：光靠 Prompt 是远远不够的。

要理解 RAG + Agent 时代为什么诞生，我们必须先回到大模型启蒙时代的"天花板"。在 2022 年底到 2023 年初，最热门的"AI 应用"就是对着 ChatGPT 写提示词。产品经理们发现，精心设计的 Prompt 确实能让模型输出质量提升数倍，但有几个根本性的问题无法解决：模型不知道你公司的内部政策、不知道昨天的股价、不能帮你查邮件、不能操作你的 CRM 系统。它就像一个博学但闭门不出的学者——什么都懂一点，但什么都不做。

更重要的是，那时候的产品架构本质上是"传统架构 + AI API"——AI 是外挂的、可选的、可替换的。这就像一个餐厅请了一位超级厉害的翻译，但餐厅本身的运营模式没有任何改变。真正的变革，要等到 AI 从"插件"变成"基础设施"。

企业级场景的痛点更加明显。一位银行的高管问："能不能让 AI 帮我审贷款申请？"答案是：可以，但 AI 不知道贵行的风控规则。一位医院的信息科主任问："能不能让 AI 辅助诊断？"答案是：可以，但 AI 读不了贵院的电子病历。一位律师事务所的合伙人问："能不能让 AI 查判例？"答案是：可以，但 AI 的"知识"截止到训练数据的时间点。没有外部记忆和外部工具，AI 只能是一个聪明的聊天机器人，而不是一个能干活的员工。

"Prompt Engineering 是给 AI 一副好嗓子。RAG 和 Agent 是给 AI 装上记忆和手脚。" —— 2023 年一位 AI 应用开发者的总结

两大解决方案在 2023 年同时涌现：

RAG（检索增强生成）解决的是"记忆"问题。它的思路极其朴素：用户提问时，先从一个外部知识库（比如企业的文档、数据库、网页）中检索出最相关的片段，把这些片段和用户的原始问题一起塞给 LLM，让它"基于这些资料来回答"。这就像让 AI 开卷考试——它不需要背诵所有知识，只需要知道去哪里查、查到了怎么组织答案。RAG 把 AI 从一个"背诵者"变成了"研究员"。

Agent（智能体）解决的是"手脚"问题。它的核心思想是：给 AI 一套可以调用的工具（搜索 API、计算器、数据库查询、邮件发送、日历创建……），让 AI 自己判断"为了完成这个任务，我需要调用哪些工具、按什么顺序调用"。GPT-4 在 2023 年推出的 Function Calling API 是这个方向的关键基础设施。Agent 把 AI 从一个"对话者"变成了"执行者"。

五股推动力

① Hallucination crisis（幻觉危机）：2023 年初，大量企业试点 AI 项目因为"AI 胡说八道"而失败。一个著名的案例是：某律师用 ChatGPT 写法庭文件，结果 AI 编造了完全不存在的判例。这个事件登上了新闻头条，让企业对 AI 的"可信度"产生了严重质疑。"如果不解决幻觉问题，AI 永远进不了严肃业务场景"——这是 RAG 成为主流架构的直接动力。

② Knowledge cutoff（知识截止时间）：GPT-4 的训练数据截止到 2023 年 4 月，之后发生的事它一概不知。企业的私有数据（内部文档、客户记录、产品手册）从未出现在训练数据中。这意味着：即便模型再聪明，它对"你的业务"也是盲人摸象。 RAG 让企业能把 AI 接入自己的数据，而不需要重新训练一个模型。

③ Enterprise adoption barrier（企业采纳门槛）：2023 年中，"AI 赋能"成为每一家大企业的战略议题，但 IT 部门的反馈很一致："我们不能把客户数据发给 OpenAI 的公有 API。"这催生了私有化部署的需求——企业需要在自己可控的环境中运行 AI，并确保 AI 只访问被授权的数据。RAG 架构天然适合私有化：知识库留在本地，只有检索到的片段传给模型。

④ Tool use emergence（工具使用能力的涌现）：2023 年 3 月，GPT-4 发布的同时推出了 Function Calling API。这是 LLM 第一次能"结构化地调用外部工具"——模型输出的不是自然语言，而是一个 JSON 格式的函数调用指令（如 {"function": "get_weather", "args": {"city": "北京"}}）。这个看似简单的 API 彻底改变了 AI 的能力边界：AI 不再只是"说话"，它可以"行动"。

⑤ Agent frameworks（Agent 框架的爆发）：LangChain（2022 年底发布，2023 年爆发）、AutoGPT（2023 年 4 月 GitHub 星标数一周破 10 万）、BabyAGI（2023 年 4 月）……这些框架证明了一件事：AI 可以自主地分解任务、调用工具、观察结果、调整策略。Agent 框架把"AI 能做什么"的想象力从"回答一个问题"扩展到了"完成一个项目"。

那么，科学认知发生了怎样的变化？最核心的认知迁移是：从"AI as a chatbot"到"AI as a system component"。2022 年，人们把 AI 看作一个对话界面；2023–2024 年，人们开始把 AI 看作一个可以嵌入任何系统的"认知模块"——它接收输入（问题+上下文+工具）、执行推理、产生输出（答案+行动）。这个认知转变的深远影响是：产品经理开始像设计"微服务"一样设计"AI 模块"——每个模块有明确的输入输出、有状态管理、有错误处理、有成本预算。

另一个深刻的认知转变是"数据工程 > 模型工程"。2023 年初，所有人的目光都集中在"哪个模型最强"上。但到 2023 年底，实践者们发现：决定 RAG 系统质量的往往不是模型，而是数据准备——文档怎么切分、嵌入模型怎么选、检索策略怎么调、重排序怎么做。 这催生了一个全新的工种："RAG 工程师"——他们的核心技能不是训练模型，而是搭建和维护高质量的知识管道。

为什么是RAG + Agent而不是别的方向？因为 Prompt Engineering 把 AI 的能力天花板推到了一个点：模型本身足够聪明，但缺乏记忆和行动力。RAG 补上了记忆，Agent 补上了行动力。当两者结合时，AI 第一次具备了"理解任务 → 检索信息 → 调用工具 → 生成结果"的完整闭环——这让它从"玩具"变成了"工具"。

关键事件时间线

  • 2023 GPT-4 发布并推出 Function Calling API——LLM 第一次能结构化调用外部工具。
  • 2023 LangChain 框架快速迭代，成为连接 LLM、数据源和工具的事实标准。
  • 2023 Meta 开源 LLaMA，开源大模型生态爆发，降低了企业私有化部署的门槛。
  • 2023 AutoGPT 在 GitHub 上一周获 10 万星标——AI 自主完成任务的愿景引发全球热议。
  • 2023 向量数据库（Pinecone、Weaviate、Chroma）成为 AI 基础设施的热门赛道。
  • 2024 RAG 成为企业级 AI 应用的"标准架构模式"——几乎每个 LLM 应用都包含检索层。
  • 2024 Dify、Flowise 等可视化 LLM 应用开发平台崛起，让非工程师也能搭建 RAG/Agent 应用。
02 / 人物

那个时代的人，在干什么

2023–2024 年，AI 领域出现了两个新角色：RAG 工程师和 Agent 开发者。他们的工作不再是"和 AI 聊天"，而是"让 AI 能查资料、能调用工具、能完成真实任务"。

小陈 · RAG 工程师

2023–2024 / AI 应用开发公司
小陈的日常工作是构建企业知识库的 AI 问答系统。他上午在"切文档"——把几百页的用户手册切成 500 字的小块；下午在调"嵌入模型"——测试哪种模型能把"退货政策"和"退款流程"映射到相近的向量；晚上在写"检索逻辑"——确保用户问"怎么退钱"时，系统能召回"退货政策"的相关段落。他的口头禅是："难点不是 LLM，而是把正确的上下文塞进提示词。" 他最骄傲的时刻：客户说"这个 AI 比客服还懂我们的产品"。

小美 · 企业数字化转型顾问

2023–2024 / 咨询公司
小美帮助 Fortune 500 公司采用 AI。她的标准话术是："不要微调，用 RAG。" 她给一家制药公司搭建了内部知识库：把 10 万页的研发文档、法规文件、临床试验报告接入 AI。现在研发人员可以直接问 AI："这种化合物在欧盟的审批要求是什么？"AI 会检索相关法规文档并给出带引用来源的回答。她的挑战是：说服法务部门"AI 的回答可以作为参考，但不能替代律师意见"。

阿强 · 独立开发者 / Indie Hacker

2023–2024 / 远程工作
阿强在巴厘岛的海边公寓里开发 AI SaaS 工具。他用 LangChain + OpenAI API + Pinecone 搭了一个"法律文书生成器"——律师上传案件信息，AI 自动生成起诉状草稿。他的成本账是这样的：每次 GPT-4 调用 $0.03，每天 1000 次调用 = $30/天 = $900/月。他设计了"模型路由"策略：简单任务用 GPT-3.5（$0.002/次），复杂任务才用 GPT-4。这样成本降低了 70%。他的最大焦虑：OpenAI 随时可能涨价，或者关闭 API。
"2023 年最让我兴奋的不是 GPT-4 本身，而是看到一家小型律所用 RAG 搭建了自己的案例检索系统——投入不到 1 万美元，效果媲美几十万美金的传统法律数据库。" —— 一位 AI 应用开发者的观察
03 / 产品

那个时代诞生了什么

RAG + Agent 时代的产品分为三类：让 AI 有记忆的工具（RAG/向量数据库）、让 AI 有手脚的框架（Agent 框架）、以及直接面向用户的"AI 搜索"产品。

LangChain

2022 · LLM 应用开发框架

最火的 LLM 应用框架。提供"链式"工作流编排——把模型调用、API 调用、知识库检索串联起来。它的核心理念是：复杂 AI 应用不是一次模型调用，而是多个步骤的流水线。代表产品：文档问答、SQL 生成、多步骤推理。

LlamaIndex

2022 · 数据框架 for LLM

专注于数据连接——让大模型能访问企业内部数据（PDF、数据库、API）。相比 LangChain 的"通用编排"，LlamaIndex 更聚焦于"如何让 AI 读懂你的文档"。它是 RAG 系统的核心组件。

Pinecone / Weaviate / Chroma

2019 / 2018 / 2022 · 向量数据库

向量数据库是 RAG 的基础设施。它们存储"嵌入向量"（文本的数学表示），支持"语义搜索"——找"意思相近"的内容，而非"关键词匹配"。Pinecone 是托管服务，Chroma 是开源本地方案，Weaviate 支持多模态向量。

Dify / Flowise

2023 · 可视化 LLM 开发平台

让非程序员也能搭建 AI 应用。Dify 提供可视化工作流编排、提示词管理、知识库构建；Flowise 基于 LangChain，用拖拽方式连接节点。它们代表了"AI 应用开发的低代码化"趋势。

Perplexity AI

2022 · AI 搜索引擎

AI 时代的"搜索引擎"。不是返回链接列表，而是实时搜索网络并生成带引用来源的综合回答。它是 RAG 思想在消费级产品中的最佳实践——每次回答都附带来源链接，用户可以验证。

AutoGPT / BabyAGI

2023 · 自主 AI Agent

让 AI 自主设定目标并执行。你给 AutoGPT 一个任务（如"帮我调研电动汽车市场"），它会自动分解为子任务、搜索信息、总结报告。虽然早期版本不太稳定，但它展示了"自主 AI"的愿景。

Microsoft 365 Copilot

2023 · 企业级 AI 助手

AI 嵌入 Word、Excel、PowerPoint、Outlook。在 Word 里帮你写文档，在 Excel 里帮你分析数据，在 Outlook 里帮你写邮件。代表了"AI 作为办公基础设施"的方向。

Claude 3 with 100K+ Context

2024 · 长上下文模型

Anthropic 的 Claude 3 支持 200K tokens 的上下文窗口（约 15 万字），可以直接"读"完一本书再回答相关问题。这是 RAG 的替代方案：如果窗口够大，直接把整本书塞进去，不需要检索。

04 / 认知

那个时代的人，心里在想什么

RAG + Agent 时代带来了四个关键认知转变——它们决定了企业如何采纳 AI、开发者如何设计 AI 系统、用户如何信任 AI。

认知一：记忆 > 智商

人们发现，给 AI 访问正确数据的能力，比用更大的模型更重要。 一个 GPT-3.5 + 高质量知识库的系统，往往比裸 GPT-4 回答得更准确。这改变了企业的 AI 策略：不再追逐最新最大的模型，而是专注于"如何把自己的数据喂给 AI"。

认知二：工具 = 手脚

AI 没有工具的 AI 只是聊天机器人；有工具的 AI 是员工。Function Calling 让 AI 第一次能"做事"——查数据库、发邮件、调 API、写代码。产品设计的核心问题变成了：给 AI 配什么工具？在什么环节调用？如何处理工具调用失败？

认知三：检索 > 背诵

对于企业应用，RAG 比微调（Fine-tuning）更实用。微调需要大量标注数据和算力；RAG 只需要把文档扔进向量数据库。而且 RAG 的回答可以标注来源，让用户验证——这是企业合规的关键要求。

认知四：成本 = 架构约束

GPT-4 每次调用 $0.03，百万级用户意味着每天几十万美元的账单。成本不再是"运营费用"，而是"架构设计约束"。 工程师开始设计"模型路由"：简单问题用 GPT-3.5，复杂问题用 GPT-4；缓存常见问题的回答；用本地小模型处理敏感数据。

05 / 关键词

关键词词典

RAG + Agent 时代的核心术语。理解这些词，就理解了如何让 AI 从"聊天机器人"变成"业务系统"。

KEYWORD 01

检索增强生成
RAG (Retrieval-Augmented Generation)

解决 LLM"幻觉"和"知识过时"的核心技术。流程：用户提问 → 从知识库检索相关文档 → 把检索结果+用户问题一起喂给 LLM → LLM 基于真实信息生成回答。通俗理解：让 AI 先"查资料"再"答题"，而不是凭记忆瞎说。

KEYWORD 02

向量数据库
Vector Database

专门存储和检索"嵌入向量"的数据库。支持语义搜索——找"意思相近"的内容，而非关键词匹配。通俗理解：传统数据库按"精确匹配"查找，向量数据库按"语义相似度"查找。 代表：Pinecone、Weaviate、Chroma、Milvus。

KEYWORD 03

嵌入向量
Embedding

把文本、图像等内容转化为高维空间中的数字向量。语义相近的内容在向量空间中距离更近——比如"苹果"和"水果"的距离很近，和"汽车"很远。通俗理解：给每个概念一个"坐标"，语义相似的概念坐标相近。

KEYWORD 04

分块
Chunking

把长文档切分成小片段（通常 200–1000 字），以便检索时精准匹配。分块策略直接影响 RAG 效果：切得太细会丢失上下文，切得太粗会降低检索精度。通俗理解：把一本书切成便利贴，每张便利贴上写一个知识点。

KEYWORD 05

智能体
AI Agent

能自主感知环境、制定计划、调用工具、执行任务的 AI 系统。不是"一问一答"，而是"你给一个目标，它自己想办法完成"。通俗理解：Agent = AI 员工，能独立完成任务。

KEYWORD 06

函数调用
Function Calling

让 LLM 根据用户请求判断需要调用哪个外部 API，并生成调用参数。模型"决定"要做什么，然后"执行"。通俗理解：给 AI 一张"工具清单"，AI 自己决定用哪把工具。

KEYWORD 07

工具使用
Tool Use

比 Function Calling 更广的概念，包括调用 API、查询数据库、使用计算器、执行代码等。Anthropic 的 Claude 和 OpenAI 的 GPT 都支持 Tool Use。通俗理解：Function Calling 是"打电话"，Tool Use 是"使用任何工具"。

KEYWORD 08

推理+行动
ReAct (Reasoning + Acting)

Agent 的核心设计模式：AI 先"思考"（Reasoning）——分析问题、制定计划；再"行动"（Acting）——调用工具、获取信息；然后"观察"结果，再思考下一步。通俗理解：像侦探破案——先推理，再找线索，再推理，循环直到解决。

关键词之间的联系

  • 文档→ 经过 →Chunking（分块）→ 生成 →Embedding（嵌入）→ 存入 →Vector DB
  • 用户提问→ 触发 →语义检索→ 从 →Vector DB→ 获取 →相关上下文→ 输入 →LLM→ 生成 →RAG 回答
  • Agent→ 使用 →ReAct 模式→ 调用 →Function Calling→ 使用 →Tools（API/DB）
  • RAG 成本<Fine-tuning 成本→ 所以企业优先选择 →RAG

易混淆概念辨析

RAG vs Fine-tuning
RAG（检索增强）

把文档存入向量库，查询时检索相关片段。优点：数据实时更新、可溯源、成本低。缺点：依赖检索质量。

vs
Fine-tuning（微调）

用领域数据继续训练模型。优点：模型本身学会领域知识。缺点：需要大量数据、训练成本高、知识不能实时更新。

产品经理建议

先尝试 RAG，90% 的场景够用了。只有当 RAG 无法满足时才考虑微调。

Vector DB vs Traditional DB
传统数据库（MySQL）

按精确条件查询。问"苹果"只返回包含"苹果"二字的结果。适合：结构化数据、精确匹配。

vs
向量数据库（Pinecone）

按语义相似度查询。问"水果"也会返回"苹果""香蕉"。适合：非结构化文本、语义搜索。

RAG + Agent 时代的启示

RAG + Agent 时代的核心突破是：AI 从"会说话"进化到了"能查资料、能调用工具、能完成任务"。 这意味着 AI 不再是玩具，而是可以嵌入真实业务流程的生产力工具。

但这个时代的 AI 仍然是"单个工作者"——一个 Agent 处理一个任务。当任务变得足够复杂（如"调研竞品 + 写分析报告 + 制作 PPT + 发送给团队"），我们需要多个 AI 协同工作。这就是下一个阶段：Multi-Agent 编排。
